Rust Integration


NO_STD ENVIRONMENT

#![no_std] disables standard library:
  - No heap allocator
  - No panic runtime
  - No file I/O, networking
  
Required language items:
  #[panic_handler]
  #[lang = "eh_personality"]


CONFIGURATION

Cargo.toml:
  crate-type = ["staticlib"]
  panic = "abort"
  
Target: i686-unknown-linux-gnu


MEMORY MANAGER

Static state:
  ALLOCATED_PAGES: AtomicU32    Number of pages currently allocated
  NEXT_PAGE: AtomicU32          Next fresh page address (monotonic bump)
  FREE_LIST: FreeList           Fixed-size stack of recycled addresses
  MEMORY_MANAGER: MemoryManager Tracks free page count

Constants:
  TOTAL_PAGES   = 1024
  PAGE_SIZE     = 4096
  MIN_PAGE_ADDR = 0x100000
  MAX_PAGE_ADDR = MIN_PAGE_ADDR + (TOTAL_PAGES * PAGE_SIZE)


EXPORTED FUNCTIONS

All use extern "C" for C ABI:

rust_memory_init()
  Reset allocator: zero ALLOCATED_PAGES, reset NEXT_PAGE to
  MIN_PAGE_ADDR, clear the free-list.

rust_allocate_page() -> u32
  Allocate a 4KB-aligned physical page.
  Checks free-list first; falls back to bumping NEXT_PAGE.
  Returns 0 if all pages are exhausted.

rust_free_page(page: u32)
  Push the page back onto the free-list for reuse.
  Validates alignment and address range before accepting.

rust_print_stats()
  Print allocated/free page counts to the terminal.

rust_get_total_memory() -> u32
rust_get_free_memory() -> u32


FFI IMPORTS

Calls C functions:

extern "C" {
    fn terminal_writestring(s: *const u8);
    fn terminal_putchar(c: u8);
}


ATOMIC OPERATIONS

AtomicU32 provides lock-free synchronization:

fetch_add(n, Ordering::SeqCst)
  Atomically increment and return old value

SeqCst = Sequential consistency (strongest ordering)


ALLOCATION ALGORITHM

  Allocate:
    1. Pop from FREE_LIST if non-empty -- return that address.
    2. CAS NEXT_PAGE from current to current+PAGE_SIZE.
    3. Return 0 if NEXT_PAGE >= MAX_PAGE_ADDR.

  Free:
    1. Validate page is aligned and within valid range.
    2. Push address onto FREE_LIST.
    3. Decrement ALLOCATED_PAGES, increment free_pages.

FREE_LIST is a plain array (TOTAL_PAGES slots) used as a stack. Safe on
uniprocessor; SMP would require atomic push/pop.


SAFETY

Unsafe required for:
  - Global mutable static
  - Calling FFI functions
  - Raw pointers

Minimal unsafe surface area.
