Interrupt Handling


INTERRUPT DESCRIPTOR TABLE (IDT)

The IDT maps interrupt vectors to handler addresses.

Structure:
  256 entries, each 8 bytes
  Entry format:
    base_low (16-bit)     Lower handler address
    selector (16-bit)     Code segment selector  
    zero (8-bit)          Reserved (must be 0)
    flags (8-bit)         Gate type and DPL
    base_high (16-bit)    Upper handler address


INITIALIZATION

Flow in idt_init():

  1. Set IDT pointer (limit and base address)
  2. Clear all 256 entries to zero
  3. Load IDT register with lidt instruction

Located in kernel/idt.c and kernel/idt_load.asm.


GATE TYPES

Trap Gate (0x8F):
  Does not disable interrupts
  Used for system calls

Interrupt Gate (0x8E):  
  Disables interrupts on entry
  Used for hardware interrupts


PROGRAMMABLE INTERRUPT CONTROLLER

The 8259 PIC manages hardware interrupts.

Ports:
  PIC1: 0x20 (command), 0x21 (data)
  PIC2: 0xA0 (command), 0xA1 (data)

Remapping:
  IRQ 0-7  mapped to INT 32-39
  IRQ 8-15 mapped to INT 40-47

Functions in kernel/pic.c:
  pic_remap()         Initialize PIC with new offsets
  pic_send_eoi()      Signal end of interrupt
  irq_set_mask()      Disable specific IRQ line
  irq_clear_mask()    Enable specific IRQ line


EXCEPTION HANDLER

isr_handler() in kernel/interrupt_handlers.c handles INT 0-31.

On any exception it sets the terminal to red-on-white and prints:

  - Exception number and name (from exception_messages[])
  - EIP (faulting instruction address)
  - Error code (pushed by CPU for faults that have one)
  - CS and EFLAGS

After printing, the kernel halts in an infinite loop. There is no recovery
path; the output is meant to give the developer enough context to locate
the fault without a debugger attached.

print_hex() in interrupt_handlers.c renders a u32 as 8 uppercase hex digits
using only terminal_writestring — no sprintf or libc dependency.


IRQ DISPATCH AND EOI ORDERING

irq_handler() in interrupt_handlers.c sends EOI to the PIC before calling
subsystem handlers:

  1. If IRQ came from PIC2 (int_no >= 40): send EOI to PIC2 (0xA0)
  2. Always send EOI to PIC1 (0x20)
  3. Call timer_handler() or keyboard_handler() as appropriate

task_switch() must only be called after EOI has been sent. The current call
chain (irq_handler -> timer_handler -> task_switch) satisfies this. Calling
task_switch from a path where EOI is pending will cause a spurious IRQ storm
when EFLAGS is restored by popf at the end of the context switch.


LIMITATIONS

- No interrupt handlers registered dynamically at runtime
- Page fault handler installed but no recovery (halts on first fault)
- No SMP interrupt routing
